    Select plaintext attack ¶

    Let's take an example, if we have a cryptographic oracle, but we don't know n and e, then

    1. We can get n by encrypting oracle.
    2. Smaller in e ( e<264e<264(At the time, we can use Pollard's Kangaroo Algorithm Algorithms to obtain e. This is more obvious.

    We can encrypt 2,4, 8, 16. Then we can know.

    c2=2eModNc2=2emodn

    c4=4eModNc4=4emodn

    c8=8eModNc8=8emodn

    So then

    c22≡c4ModNc22≡c4modn

    c32≡c8ModNc23≡c8modn

    Therefore

    c22−c4=KNc22−c4=kn

    c32−c8=tNc23−c8=tn

    We can find the maximum common factor of kn and tn, and the probability is n. We can also construct more examples to always look for n with more certainty.

    Arbitrary ciphertext decryption ¶

    Suppose Alice created the ciphertext. C=PeModNC=Pemodn And send C to Bob, and assuming that we want to decrypt any ciphertext that is encrypted by Alice, rather than just decrypting C, then we can intercept C and use the following steps to find out P:

    1. Choose any. X∈Z∗NX∈Zn∗the X and N intercomens
    2. Calculations Y=C×XeModNY=C×Xemodn
    3. Since we can select ciphertext attacks, we get the decryption results of Y. Z=YdZ=Yd
    4. Well, because Z=Yd=(C×Xe)d=CdX=PedX=PXModNZ=Yd=(C×Xe)d=CdX=PedX=PXmodnBecause X and N are interoperable, we can easily get the corresponding inverse, and then we can get P.

    RSA parity oracle¶

    Suppose there is an Oracle that decrypts a given ciphertext, and checks the oddity of the decrypted explicit text and returns the corresponding value based on parity, such as 1 for odd and evenly. Given a encrypted ciphertext, we only need log(N) times to know the plaintext message corresponding to this ciphertext.

    Principle ¶

    Assumption

    C=PeModNC=PemodN

    The first time, we can send it to the server.

    C∗2e=(2P)eModNC∗2e=(2P)emodN

    The server will calculate.

    2PModN2PmodN

    Here

    • 2P is even, and its power is even.
    • N is odd because it is multiplied by two large prime numbers.

    So then

    • The server returns an odd number, i.e. 2PModN2PmodN If it is odd, it means that 2P is greater than N, and the odd number of N is subtracted, and because 2P<2N2P<2NSo we subtract an N, i.e. N2≤P<NN2≤P<NWe can also consider moving down.
    • If the server returns an even number, 2P is less than N. i.e. 0≤P<N20≤P<N2We can also go down.

    Here we use mathematical induction, that is, suppose that at the time i,XN2i≤P<XN+N2ixN2i≤P<xN+N2i

    Further, at i+1, we can send

    C∗2(i+1)eC∗2(i+1)e

    2i+1PModN=2i+1P−KN2i+1PmodN=2i+1P−kN

    0≤2i+1P−KN<N0≤2i+1P−kN<N

    2018 Google CTF Perfect Secrecy¶

    Here is an example of the 2018 Google CTF.

    #!/usr/bin/env python3
import sys
import random

from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.backends import default_backend


def ReadPrivateKey(filename):
  return serialization.load_pem_private_key(
      open(filename, 'rb').read(), password=None, backend=default_backend())


def RsaDecrypt(private_key, ciphertext):
  assert (len(ciphertext) <=
          (private_key.public_key().key_size // 8)), 'Ciphertext too large'
  return pow(
      int.from_bytes(ciphertext, 'big'),
      private_key.private_numbers().d,
      private_key.public_key().public_numbers().n)


def Challenge(private_key, reader, writer):
  try:
    m0 = reader.read(1)
    m1 = reader.read(1)
    ciphertext = reader.read(private_key.public_key().key_size // 8)
    dice = RsaDecrypt(private_key, ciphertext)
    for rounds in range(100):
      p = [m0, m1][dice & 1]
      k = random.randint(0, 2)
      c = (ord(p) + k) % 2
      writer.write(bytes((c,)))
    writer.flush()
    return 0

  except Exception as e:
    return 1


def main():
  private_key = ReadPrivateKey(sys.argv[1])
  return Challenge(private_key, sys.stdin.buffer, sys.stdout.buffer)


if __name__ == '__main__':
  sys.exit(main())

    You can see

    • We can give the server two numbers, and the server will decide which one to use based on the decryption of the ciphertext content.
    • The server will be used. random.randint(0, 2)To generate random numbers and output the relevant random 01 bytes c.

    At first glance, it seems completely random, check it out. random.randint(0, 2)It can be known that its generation of random numbers includes boundaries, so the probability of generating an even number is greater than the probability of generating an odd number, then the probability of c and p is 2/3. We can then set m0 and m1 to know whether the last ciphertext after decryption is 0 or 1. This is RSA parity oracle.

    RSA Byte Oracle¶

    Suppose there is an Oracle, which decrypts a given ciphertext and gives the last byte of the plaintext. So given an encrypted ciphertext, we just need Log256Nlog256⁡n The next time you can know the plaintext message corresponding to this ciphertext.

    Principle ¶

    This is actually an extension of RSA parity Oracle, since the last byte can be leaked, then the number of times we get the ciphertext corresponding to the plaintext should be reduced.

    Assumption

    C=PeModNC=PemodN

    The first time, we can send it to the server.

    C∗256e=(256P)eModNC∗256e=(256P)emodN

    The server will calculate.

    256PModN256PmodN

    Here

    • 256P is an even number.
    • N is odd because it is multiplied by two large prime numbers.

    Since P is usually less than N, then256PModN=256P−KN, ,K<256256PmodN=256P−kn,k<256. . And for two different. K1, ,K2k1,k2We have

    256P−K1N≢256P−K2NMod256256P−k1n≢256P−k2nmod256

    We can use counter-evidence to prove the above inequalities. Simultaneously 256P−KN256P−kn The last word is actually −KN−kn It is obtained in the case of mode 256. So, in fact, we can first enumerate the last byte in the case of 0~255, and construct a map of k and the last byte map.

    When the server returns the last byte b, then we can tell that k is deducted from the map table of the above structure, i.e., k of N, i.e. KN≤256P≤(K+1)NkN≤256P≤(k+1)N. .

    Since then, we have used mathematical induction to get the range of P, i.e., assuming that at the time i,XN256i≤P<XN+N256ixN256i≤P<xN+N256i

    Further, at i+1, we can send

    C∗256(i+1)eC∗256(i+1)e

    The server will calculate.

    256i+1PModN=256i+1P−KN256i+1PmodN=256i+1P−kN

    0≤256i+1P−KN<N0≤256i+1P−kN<N

    KN256i+1≤P<KN+N256i+1kN256i+1≤P<kN+N256i+1

    According to the results of the second

    256XN256i+1≤P<256XN+256N256i+1256xN256i+1≤P<256xN+256N256i+1

    We can assume here. K=256Y+tk=256y+tHere t is what we can get through the mapping table.

    256YN+tN256i+1≤P<256YN+(t+1)N256i+1256yN+tN256i+1≤P<256yN+(t+1)N256i+1

    At the same time, since P necessarily exists, the range obtained by i+1 and the range of the i-second obtained must have an intersection.

    So y must be equal to x.

    Further, we can summarize this in the initial case.

    lb = 0

    Suppose the server returns b, then

    k = mab[b]
interval = (ub-lb)/256
lb = lb + interval * k

    from Crypto.Util.number import *
mm = bytes_to_long(b'12345678')

def genkey():
    while 1:
        p = getPrime(128)
        q = getPrime(128)
        e = getPrime(32)
        n = p * q
        phi = (p - 1) * (q - 1)
        if GCD(e, phi) > 1:
            continue
        d = inverse(e, phi)
        return e, d, n

e, d, n = genkey()
cc = pow(mm, e, n)

    cs = (cc * pow(ss, e, n)) % n
